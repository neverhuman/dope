# TabSyn numeric operation admission

This extends the generated CPU adapter with a separately anchored operation
grant. It prepares real numeric regression fit, sample and native evaluation;
it does not launch a population job or certify a GPU runtime.

An admitted operation must bind the original runtime and author commit,
the executing adapter and guard, the complete canonical job and configuration,
TRAIN-derived input hashes, a live caller/controller identity, and a frozen
capacity declaration. The reviewed external guard owns fresh cross-host
admission, measured CUDA providers, the inherited GPU lease, the outer
600-second watchdog and closure receipts. Missing or changed grants reject
before numerical dependency initialization. Runtime custody remains separate
from a one-operation grant.

## Native selection

The regression KPI calls the immutable author `_evaluate_regression` with its
36 auditor configurations and four post-selection refits, then selects the
generator configuration by `best_r2_scores.XGBRegressor.r2`. Real validation
does not select the auditor hyperparameters. The author's synthetic internal
validation labels remain raw, while its fit and real labels use the original
float32 log clipping. This behavior is preserved and reported.

Only the target is inverse-mapped from the frozen TRAIN projection to its
TRAIN-clipped source units before that author transform. The common evaluator
continues to consume the original projection. Validation rows are derived
from the official training partition. Constant author-transformed targets or
insufficient usable row groups retain the default with no native winner.
Those outcomes require verified input custody.

Native scores from different methods cannot rank those methods. All failed
and timed-out generator trials remain in the eight-trial and 43,200-second
cell history, including verified prior attempts and admission waiting time.

## Explicit compute scaling

The original author-default track retains 4,000 VAE epochs and up to 10,001
diffusion epochs. A separate preregistered population track uses 200 VAE
epochs and up to 1,000 diffusion epochs, with beta 0.01 or 0.001. The author
diffusion patience of 500, model definitions, losses, optimizers and 50-step
sampler remain unchanged. The beta grid is campaign-defined.

Both tracks retain the 600-second whole-operation ceiling and 16-GiB GPU
admission ceiling. A deadline-truncated checkpoint cannot become an eligible
fit. An author patience stop must be recorded separately from deadline expiry.
No real-data outcome selected this preregistered scaled budget, and its actual
GPU feasibility has not yet been measured.

## Qualification and evidence

Real admission requires actual, source-bound generated CUDA fit/sample replay
closure; native admission additionally requires the original auditor closure.
Generated CPU checks, mocked grants and numerical fixtures establish source
contracts only. Every caller must preserve referenced qualification receipts,
actual process exits, source/runtime/artifact hashes and final deadline checks.
Bulk output stays on the owner-amended xbabe3 local scratch filesystem, under
its independent 200,000,000,000-byte aggregate admission ceiling.

Official tests stay sealed. MFS-v2, PTF-v1, release-safe L3 and superiority
remain null. No TabSyn population fit or matched-result measurement is implied
by this preparation.
