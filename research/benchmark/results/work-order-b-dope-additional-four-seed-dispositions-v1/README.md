## Receipt digest serialization

All aggregate digests use SHA256 of UTF-8 canonical JSON with `sort_keys=True`, `separators=(",", ":")`, `allow_nan=False`, `ensure_ascii=True`, and no trailing newline. Fit records contain `dataset_lineage_id`, `fit_seed`, `receipt_bytes`, `receipt_sha256`, sorted by lineage then numeric fit seed. Metric records contain `dataset_lineage_id`, `fit_seed`, `sample_seed`, `size_multiplier`, `receipt_bytes`, `receipt_sha256`, `synthetic_sha256_declared`, sorted by lineage, numeric fit seed, numeric sample seed, numeric size. A per-fit digest hashes the six complete metric records filtered by lineage and fit seed, in that same order. JSON object keys are sorted by the serializer; arrays keep the stated order. These hashes bind receipt metadata; they do not freshly verify sample or model payloads.
