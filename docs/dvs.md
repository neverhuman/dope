# Downstream Value Suite v1

`dvs::evaluate(&DvsRequest)` consumes a frozen roster of paired losses and evaluator-owned grouped driver evidence. Preprocessing and learner fitting occur upstream; real TEST outcomes never enter synthetic-validation model selection. Requests bind FIT, real TEST, preparation, groups and roster hashes, and explicit scheduled cells. Missing, failed, timed-out and unsupported cells remain in the receipt. New issuance also requires the versioned `declared_roles` object (`dope.dvs.declared-evidence-roles/v1`): `real_fit_usage=fit_only`, `synthetic_validation_usage=model_choice`, and `real_test_usage=assessment_only`. The FIT and TEST view hashes must match the common FIT/TEST pins and must differ from each other; TUNE has a separate explicit view hash and may not reuse the TEST hash. The binding digest covers the fixed domain, labels, three view hashes and all five duplicated common pins in the Rust field order. It checks declaration structure only; it does not authenticate a principal or prove row origin/disjointness. A historical receipt without `role_binding` remains schema-readable but is unverified; no new receipt is issued from a request missing the declaration.

R is the unclipped `(L_null-L_syn)/(L_null-L_real)` on a common real query. Explicit positive absolute/relative real-gain floors and a positive real-gain LCB gate eligibility. Family means are descriptive; robust retention is unavailable when required scheduled evidence is missing. D uses the canonical C02 full-family simultaneous bounds, positive floors and aligned pins, with `driver-rank-informative-v1` grouped rank semantics. Real ties do not create perfect evidence. A descriptive ratio cannot grant D80 or release qualification.

S_select chooses a roster index using synthetic validation alone and reports real-trained real-test regret. Synthetic-validation ties are uninformative. S_transfer reports informative pairwise agreement between real-trained and synthetic-trained rankings on the same real test population. The fixed roster hash binds vector order.

`dvs::permutation::grouped_permutation_importance` accepts a frozen prediction callback, moves every column of a declared semantic group together, and checks its prediction-call budget before any call. It produces evaluator evidence; it does not fit a learner or generate simultaneous inference. Correlated/conditional perturbation designs and scientific calibration remain separate protocol obligations.

Payload/closure receipts count and hash actual supplied bytes: packet, public schema and mandatory sidecars; shared decoder closure and owner-private dependencies are reported separately. Clean-room sampling is `not_run`. Optional bounded privacy diagnostics count exact copies and compare median prepared-space nearest-neighbor distances against a real-holdout reference. These are empirical diagnostics, not formal DP, de-identification or a memorization bound.

`dvs::receipt::audit_card` renders these computed fields directly. Missing required metric evidence yields incomplete state. Qualification, formal DP and release authorization remain `not_run` even on a complete evidence fixture. CLI callers must map malformed request/serde failures to a stable source-free error; never print raw parse errors or raw source-bearing fields. Receipt schema: `schemas/dope-dvs-receipt-v1.schema.json`.

Validation: `cargo test --manifest-path engine/Cargo.toml --locked -p dope-core --test dvs`; canonical C02 old corpus and informative-rank fixtures are shared with the root metric core. The historical golden arithmetic tolerance is 1e-12. No dataset campaign or quality claim is established by these fixtures.
