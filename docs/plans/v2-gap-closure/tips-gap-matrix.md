## arena

The documents ask for three named emissions from one packet (faithful or 'standard', distill, matched), an n_fit-driven row policy, and a stateless row-addressable sampler whose rows are identical under any batch size, chunking or thread count, with shared random numbers across candidate packets and no batch statistic, forced class or fitting at sampling time. ## marginals

The documents ask for a typed per-column law: decimal lattice detected on the raw column (coarsest q0 in {1,2,2.5,5}x10^d, >= 99.5% on grid, 2e-3 tolerance, f32-aware), heaping masses, atoms (<= 32, count >= max(k, 0.005n), >= 3x expectation), tier supports 24/64/256, k-th order-statistic tails with W1 knots, missing as a state, the same for targets, and canonical bit-identical emission. The gate is MargAUC <= 0.60 on >= 90% of Quick-24/dev tables, median feature C2ST down >= 0.10 versus engine 1.3.0 (0.987, with 0.837 expected from a decimal snap alone), retention and privacy unchanged. The repo has a real implementation, ColumnMarginalV2 (engine/dope-core/src/marginal/{v2,lattice,atoms,tails}.rs), wired into the Format-2 CATF pipeline and binary codec, with five synthetic unit tests. The decisive defect is that the pipeline fits it on model-space values (schema.to_model output), not raw values, so a raw decimal grid becomes a 1/N step the detector's candidate set matches only by coincidence; the unit tests pass because they feed raw planted columns directly. Emission then goes through an affine/exp_m1 inverse and 6-decimal formatting, there is no decimal round-trip test, regression targets get no lattice or atom treatment, and heaping keeps one multiple against a uniform expectation. No gate is measured: the only recorded realism numbers are C2ST 0.934 (v1.3.1) and 0.9045 (v2.0.0) on 22 tables from a Python RF evaluator, a drop of 0.03 against the required 0.10, with regression and binary retention falling. The measuring instruments are too coarse to see the defect: Rust MargAUC is a <= 32 quantile-bin histogram ratio, native C2ST trees split on 7 octile thresholds, and the Python MargAUC is a median rank AUC over the first 12 columns. The neural side is further away: DopeSingleEncV6 decodes every column as a 17-knot continuous spline (C2ST 0.999 per agent_chat.md) and DopeFidelityV5 copies sorted raw fit values for discrete columns. Nothing in this slice was executed; all statuses come from reading code at HEAD 7bbb6f34 and recorded result files.

Most consequential gaps:

- M01/M02: the lattice codec is fitted on model-space (scaled, sometimes log1p) values instead of raw values, so real decimal grids are mostly not detected and emission is not canonical; the unit tests miss this because they bypass the schema. This is the package the documents call the cheapest large realism gain (0.987 -> 0.837).
- M16: none of the three realism instruments (Rust <= 32-bin MargAUC, Rust octile-threshold C2ST, Python rank-AUC median over 12 columns) can see on-grid versus off-grid values, and none reports a real-vs-real reference, so G3/G4 cannot be certified or falsified today.
- M14/M15/M17: no gate measurement exists. The only proxy shows C2ST 0.934 -> 0.9045 (0.03, needs 0.10) with regression retention 0.9004 -> 0.8374 and binary 0.1529 -> 0.0845; there is no engine 1.3.0 baseline row, no snap arm, no Quick-24 manifest, no per-column ledger.
- M22/M23: the neural models are outside the column model. V6 (the zero-raw-row encoding) decodes every column as a 17-knot continuous spline and scores C2ST 0.999; V5 copies raw fit values and raw extremes, violating the k-support rule.
- M12/M08: marginal bytes are not accounted or budgeted (roughly 150 bytes per continuous column against a 2 KiB headline; the budget is not a hard cap), and regression targets get no lattice or atom treatment despite the code comment saying they do.

Repository claims not supported by code or measurements:

- CHANGELOG.md:72-74 lists 'Phase P3 ColumnMarginalV2 (... decimal lattice + f32 heritage, heaping, off-grid mixture, W1 DP knots + tails ...)' as landed. The structs and detector exist, but in the shipped pipeline they run on scaled model-space values (pipeline.rs:165, 216), so decimal-lattice behaviour on real CSV input is not demonstrated by any test or measurement.
- engine/dope-core/src/marginal/v2.rs:3 says the codec 'Covers BOTH features and targets'. No target call site exists; the regression target is emitted through NumericSpec::to_raw with only the integer flag (format2_codec.rs:149).
- CHANGELOG.md:67-68 'native 2-fold depth-3 boosted-tree C2ST & MargAUC'. The arena's MargAUC is a quantile-bin histogram ratio (realism.rs:74-134, used at dope-arena/src/report.rs:54); the boosted per-column variant (c2st.rs:205-230) is called only from tests, and its trees split on 7 octile thresholds.
- tails.rs:108 attributes 'C2ST=0.934' to boundary clamping spikes (BUG-R6) as fixed. The recorded value after the fix is 0.9045 on 22 tables with a weak Python evaluator; no ablation isolates the tail change.
- agent_chat.md:10 reports flow_v6 'c2st=0.6357 PASS, marg=0.531'. That model decodes from raw fit rows, the MargAUC is a median rank AUC over the first 12 columns, and PASS uses only c2st <= 0.70 (s3_kpi_evaluator.py:160-172, 197); it is not a pass of the spec's realism gate.
- Comments in tails.rs:6 and :18 say tail anchors are 'never raw min/max'. The n < 4 or max_knots < 4 branch returns the raw minimum and maximum (tails.rs:12-16), and for n < 100 the anchor sits below the k-th order statistic (k_ord = min(k, n/10)).

## teacher

The documents ask for a cross-fitted teacher stack (K=5, stack weights and calibration fitted inside each fold's complement, poison-tested), a student distilled onto real rows plus min(8n, 200,000) teacher-labelled probes and grown to the byte budget rather than cut at a noisy validation minimum, a direct-label control at equal bytes, noise refitted on untouched real labels, faithful/distill emission, a Max tier, and gate G2/G5 (+0.03 at n and +0.02 at 4n over engine 1.3, student >= 0.97 of teacher, at least half the cap used). A simplified version of the whole chain exists in Rust under /home/ubuntu/dope/.agent/worktrees/integration/engine/dope-core/src (teacher/, distil/, forest/soft_boost.rs, compile/v2/pipeline.rs) and is reachable through `dope fit --format 2`. None of it is measured against its gate: there is no Quick-24 panel, no engine-1.3 baseline on the same tables, and no record of teacher quality, student retention of teacher or bytes used. The only numbers are two single-row arena files on 22 tables from an evaluator whose source is not in the repo: median 0.6024 -> 0.6393 after commit 3de9035c, with binary 0.1529 -> 0.0845, regression 0.9004 -> 0.8374 and parity 0.2727 -> 0.2273, far from the tips' 0.98-0.995. That commit rewrote the linear teacher member as cyclic coordinate Newton, stratified folds by label, mined pairs on residuals, fixed main-effect purification, truncated the student to its best probe tree and added byte-cap binary search with temperature refit. The stratification makes fold assignment label-dependent, and the poison test the specs require is not actually implemented. Decisive gaps: no gate measurement or attribution, no direct-label control or SELECT-based choice, capacity hard-capped well below the budget (probes <= 4,096, teacher boosters <= 80 trees, student <= 600 trees at depth <= 5 in half the budget), leakage proof not established, and Format 2 distill emission and `dope predict` not delivered. LearningSignatureV1 is an in-sample diagnostic that departs from the E section 15 schema and changes nothing in the packet; F section 9's learned sketch encoder is superseded by H.

Most consequential gaps:

- Gate G2/G5 has never been measured and the only evidence runs against it: Format 2 scores median 0.6393 (mean 0.2217, binary 0.0845, regression 0.8374, parity 0.2273) on 22 tables from an evaluator not in the repo, with no engine-1.3 baseline on the same tables, no worst-family metric and no intervals (T19).
- No attribution exists: teacher quality, student retention of teacher, bytes used and stop reason are not computed or reported, and the S5.0 experiment was skipped, so it is unknown whether the teacher, the student trainer, capacity or the covariate model causes the shortfall (T01, T18).
- There is no direct-label control, no teacher-weight candidates, no `--teacher off`, and SELECT labels are never read, so the kill rule 'ship the control if distillation does not win at equal bytes' cannot be applied and a weak teacher is distilled unconditionally (T13, T14).
- Capacity is hard-capped far below 'fill the budget': at most 4,096 probes instead of min(8n, 200,000), teacher boosters at most 80 trees, student at most 600 depth-5 trees in half the budget even at Max, and main and pair stages fitted by least squares on clamped logits (T02, T08, T10, T17).
- Leakage safety is asserted but not proven: the poison test does not poison a fold, fold assignment and the agreement scale depend on labels, teacher-auditor independence is not enforced, and the external seam is ingest-only with an unchecked split hash and a zero-target hazard when probe predictions are missing (T03, T04, T06, T07).

## structure

The documents (H W4 + C.4/C.5, I P6/P7d, G S6, E 13/16, F 7.4/8) ask for a BUILD/SELECT-confirmed rule miner (FD, ARITH, BIN, INEQ, EXCL, MISS), a copula-anchored autoregressive tree layer with missingness as a chain state, zero-byte copula moment calibration, an owner-side entropy-balanced projection compiled back into the sampler, and a gate of median C2ST <= 0.70 that is never worse than copula-only, plus rule, driver, kappa and privacy conditions. A real first version of nearly all of this exists in Rust (ENG/src/structure, ENG/src/catf, ENG/src/copula.rs, ENG/src/compile/v2/project.rs) and is wired into fit_v2 and the Format 2 sampler, with five behavioural tests in ENG/tests/structure_catf.rs. ## compile

Path shorthand used below: ENG = /home/ubuntu/dope/.agent/worktrees/integration/engine/dope-core (lane HEAD 7bbb6f34). The documents ask for a bounded compiler that splits the owner's rows into BUILD/SELECT before fitting, audits every candidate on its exact decoded bytes with native learners, proposes seven increments ranked by gain per byte, orders candidates by fixed lexicographic buckets, enforces fit and audit budgets, picks with a clean two-learner selector, ships nested prefix tiers with carry-forward, refits the frozen recipe on all rows with lineage, and attaches a small certificate. What exists is a set of leaf utilities: a role splitter, a transitive bucket comparator, a carry-forward resolver, a damped-Newton tilt solver, a ridge distance and a 115-line generic loop skeleton. Only ENG/tests/compiler_v2.rs calls the loop, the comparator and the carry-forward resolver, and it feeds them hand-written scores and dummy byte vectors. The shipped Format 2 path (`fit_v2`, ENG/src/compile/v2/pipeline.rs:153-436) is a single fixed pass: capacity comes from a budget lookup table, no candidate is ever scored on SELECT, the P+ weights are computed and discarded, one tier entry is written, and the artifact is the BUILD-only fit (about 64% of rows) while recording n_fit as all rows. None of the gates has a recorded measurement: G5/G7 closed loop versus fixed allocation, selector regret <= 0.01, zero tier drops > 0.005, certificate error <= 0.03, compile <= 20 minutes at 20,000 x 20 on 32 threads, 36 of 36 reruns identical, fast within 0.01 of standard. The only Format 2 numbers on disk are two single-line files (/home/ubuntu/dope-data/arena/rust_format2_v131/eval.jsonl and rust_format2_v200/eval.jsonl: median retention 0.6024 and 0.6393 on 22 tables), with no tier, budget, timing or rerun dimension. The decisive gaps are therefore the missing auditor and proposal generators, the missing final refit on all rows, the absent selector and tier machinery in the product path, and the absence of any gate harness (rerun probe, compile-time benchmark, regret and tier-inversion probes).

Most consequential gaps:

- The closed loop does not exist in the product path: loop_driver.rs is a 115-line generic fold called only by a test with dummy byte vectors, there is no exact-artifact auditor and no proposal generator, and fit_v2 is a single fixed pass (CL-02, CL-03, CL-04). Every G5/G7 gate is therefore unrunnable.
- The shipped Format 2 artifact is the BUILD-only fit (about 64% of rows) with no refit on all rows, and it records n_fit as 100% of rows (CL-11). This is the cheapest change with a direct expected fidelity effect and it also fixes a mislabelled quantity.
- No selector and no tier machinery for Format 2: each byte budget is an independent compile from a lookup table, one tier entry is written, carry-forward is never invoked, and neither selector regret (<= 0.01) nor tier drops (> 0.005) has been measured (CL-09, CL-10).
- No gate harness: no rerun probe for 36 of 36, no thread-count determinism test for fit_v2, no compile-time or RSS record, no size-versus-fidelity curve at 0.5-4 KiB, no frozen dev panel or excluded-auditor protocol (CL-16, CL-17, CL-18, CL-21).
- P+ projection and the certificate are diagnostics with misleading labels: weights are discarded, gap (4) is reported as equal to gap (3) by default, the report field ridge_cert_relative_risk holds an RMSE difference, and there is no certificate section or measured certificate error (CL-13, CL-15).

Repository claims not supported by code or measurements:

- CHANGELOG.md (Engine 1.3.1, lines 78-79): 'Phase P6 P+ damped-Newton moment projection + LearningSignatureV1 + RidgeCertificate' reads as a delivered closed-loop phase. In fit_v2 the projection weights are discarded and only diagnostics are stored (pipeline.rs:328-331, 355-357); the loop, selector and carry-forward are called only from tests/compiler_v2.rs.
- engine/dope-core/src/compile/v2/loop_driver.rs:3-4: 'Every candidate move is accepted ONLY after serialize -> parse -> sample round-trip evaluation on sealed SELECT'. The driver performs none of these steps (it delegates to a closure, lines 88-101), accepts every under-cap candidate, and SELECT is by specification exposed, not sealed.
- engine/dope-core/tests/compiler_v2.rs:1-2: 'Behavioral tests for Phase P6 Closed-Loop Exact-Artifact Compiler'. The loop test feeds vec![step as u8; sz] byte vectors and constant scores (lines 156-176); no real artifact is compiled or audited. Labels T20 and T21 do not match E 25.1 (budget exhaustion, refit lineage).
- engine/dope-core/src/compile/v2/tiers.rs:15-18: 'guaranteeing zero tier inversions > 0.005'. It only orders supplied SELECT scores; nothing is measured, and G S7 records that carry-forward left two drops above 0.02 on rerun and must be described as best observed under the search.
- engine/dope-core/src/compile/v2/project.rs:1-2 and 25-27: 'full 5-gap ladder logging' and 'compiling the projected distribution directly into a stateless sampler'. The ladder has four gap fields, gap_decoded defaults to gap_compiled (line 155), and 'compiled' is a systematic resample of pool indices, not a refitted sampler.
- engine/dope-core/src/compile/v2/pipeline.rs:1-6 module header lists 'P+ damped-Newton projection + ridge_certificate -> Format 2 binary encode' as part of the wired pipeline and cites G-01, G-02, G-05; the projection does not alter the encoded program and no gate measurement exists.

All five v2 documents put the learned lane last: H gates it after G5 (W9, GPU budget D-7 only after G5), G after G7 and owner decision O-7 (R3/R4), I after G5-G7 plus hundreds of logged compiler runs, E only once the conditional-tree ceiling fails, and F only after its first batch (truthful registry, repaired protocol, native joint candidate, ceiling study). Almost nothing the documents ask of a neural result is measured. The flow_v6 / V5 sampler still reads raw fit rows at sampling time, so its 0.83-0.90 is not an encoding. The zero-raw-row DopeSingleEncV6 scores main KPI -0.08 (step 2100, 672 B formula) and -0.16 (step 850, 1040 B formula) with C2ST 0.9997 / 0.9985, and its "encoding bytes" are an arithmetic formula, never serialised, never natively decoded, and exclude the scale card and shared decoder weights. Training optimises ridge / IRLS linear proxies plus random Fourier features only; selection uses one 42-46 table panel that also feeds the training curriculum, with a strict '>' on a noisy median and a filename-stem "family" split. Before any neural number may be claimed the documents require: (1) the v3 scoreboard passing G0/G1 with real-vs-real twin references; (2) scoring after serialise, parse and native sample with whole-file bytes and decoder closure counted; (3) a row-local sampler; (4) a held-out learner family and failures kept in denominators; (5) an unexposed confirmation panel; (6) G9c non-inferiority to the closed-loop native compile at equal bytes; (7) a positive scaling curve before a second run.
