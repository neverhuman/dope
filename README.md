# D.O.P.E.: Downstream Objective-Preserving Encoding

[![CI](https://github.com/neverhuman/dope/actions/workflows/ci.yml/badge.svg)](https://github.com/neverhuman/dope/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**Compile a private table into a sampling program of about a kilobyte. Models trained on its samples learn most of what they would learn from the real rows, and, once the table is several times larger than the program, more than from the real rows that fit in the same bytes.**

DOPE compiles a table into a small **sampling program**: quantized feature marginals, a dependence tree, a compact network for the target's conditional mean and a noise model. Sampling reads the program and nothing else, every byte it reads is counted, and no training row is stored. The question it answers is the one data owners actually have: *how little do I need to ship so an outside learner can learn what my data teaches?*

## The KPI: transfer per byte

Transfer Description Length (TDL) asks how few bytes carry a table's predictive value to learners that never see the table. Its operating point is `KiB@T90/D80`: the smallest tested budget at which learners trained only on synthetic rows recover nine-tenths of the real data's gain over a null model (T90) in every learner family, keep four-fifths of the real feature drivers (D80), and pass copy and byte-accounting gates, all scored on untouched real rows ([metric](docs/metric.md)).

Bytes are the right axis because copying needs bytes in proportion to rows, while a program needs bytes in proportion to structure. A small program is cheap to audit and version, has little room to memorize rows, and shows what the learner actually needed. The figure plots the TDL frontier itself: the share of tables that clear the transfer bar at each budget.

## Quick start on a real table

```bash
cargo build --release --bin dope-kernel                     # Rust toolchain pinned in rust-toolchain.toml
python3 examples/adult/prepare.py --out target/adult        # UCI Adult, CC BY 4.0, official test split
target/release/dope-kernel fit-table --csv target/adult/train.csv --target income --out target/adult/adult.dope
target/release/dope-kernel inspect-table --model target/adult/adult.dope
target/release/dope-kernel sample-table --model target/adult/adult.dope --rows 32561 --out target/adult/synthetic.csv
pip install numpy pandas scikit-learn catboost
python3 examples/adult/evaluate.py --dir target/adult --model target/adult/adult.dope
```

`synthetic.csv` has the source header, category labels, integer columns, dates and missing-value markers. The evaluation fits logistic regression, an MLP and CatBoost on real rows, on DOPE rows, and on as many real rows as fit in the artifact's bytes, then scores all of them on the official test file. Replace the CSV and `--target` to run your own table; `--drop` removes identifier columns.

## How a raw table is normalized

`fit-table` stores an invertible plan per column, so samples decode back to the source schema:

- **Numbers** are scaled to the unit interval. Heavily skewed columns are log-scaled first, so the program's grid codes keep resolution where the data are instead of spending it on a few outliers.
- **Categories** become one code per column, with levels ordered by their smoothed target mean. The code carries each level's main effect in one coefficient. One-hot dummies would cost bytes per level and let sampled rows switch on several levels at once; apply `pandas.get_dummies` downstream, as `evaluate.py` does.
- **Dates** become day counts; **missing cells** stay missing; **rare levels** are pooled into one level when there are several; identifier-like columns are dropped and reported.

Numeric tables already on the unit interval can use `dope-kernel compile` directly, and `dope-kernel compile-csv` remains for the typed raw and mixed carriers ([CLI](docs/cli.md)).

## What changed in the core

- **Native training.** The headline residual network trains in Rust with the published optimizer settings; no libtorch or GPU is needed (`--native-target-profile`).
- **Packed values.** The artifact header records a quantization grid, so values are stored as grid codes (`--packed-codec`): about half the bytes, with bit-identical samples for the headline program shape.
- **Table workflow.** `fit-table`, `sample-table` and `inspect-table` give the end-to-end path above.

The study behind the numbers is in [research/benchmark/equal_bytes](research/benchmark/equal_bytes/README.md) and the mathematics in [docs/math.md](docs/math.md).

## Scope

Results are development validation on public regression and binary tables; the official test split stays sealed for one pre-registered run, and cross-model feature-driver preservation: not yet measured. Copy, membership and attribute checks are empirical diagnostics, not formal differential privacy and not HIPAA de-identification. Each program is conditioned on one declared target.
